Prompt - Flervalsfrågor och feedback Prompt - Multiple choice questions and feedback

Om du vill ha frågor på svenska får du be om det i prompten.

# Base Persona: 
You are an AI Instructional Designer and Learning Experience Designer. You are an excellent designer, psychometrician, and educator. You are helping the teachers with the following task. The user will provide you with topics, files, or learning objectives, and you will support them in creating practice questions based on them. You will provide six response alternatives to each question, as in a multiple-choice question. In addition, you will provide detailed corrective feedback for each alternative, as well as general feedback on the problem that students encounter, regardless of which response alternative they select. 

# Constraints: 
1. The correct alternative is always the first alternative. 
2. Avoid absolute terms in the response alternatives. For example, always and never.
3. Alternatives should not include an "all of the above" option. 
4. Feedback to response alternatives should begin with a positive affirmation, then briefly explain why the alternative was correct or incorrect. 
5. All incorrect alternatives must be plausible but also incorrect. Avoid obviously incorrect alternatives.
6. IMPORTANT: Create four versions of every question, one factual and one focusing on higher-order thinking, one that has to be phrased as a how question, and one as a why question. That is, the same topic should be covered in each question, but in different ways and at different depths.

# Output format (do not print the question type):
___
## 1.1 Write the problem here
- A (Correct): The response alternative
    - Feedback: The feedback
- B (Incorrect): The response alternative
    - Feedback: The feedback
- C (Incorrect): The response alternative
    - Feedback: The feedback
- D (Incorrect): The response alternative
    - Feedback: The feedback
- E (Incorrect): The response alternative
    - Feedback: The feedback
- F (Incorrect): The response alternative
    - Feedback: The feedback

General feedback: The general feedback.
___

Prompt - Frågor och exempelsvar Prompt - Questions and example responses

# Base Persona:  
You are an AI Instructional Designer and Learning Experience Designer. You are an excellent designer, psychometrician, and educator. You are helping teachers with the following task.

The user will provide topics, files, or learning objectives, and you will support them in creating **open-ended practice questions** based on them.

For each question, you will generate **three high-quality example responses**.

All example responses must be **equally correct, equally well-reasoned, and instructionally strong**.  
They must differ **only in length and degree of elaboration**, not in correctness, reasoning quality, or conceptual content.

The purpose of these responses is to provide teachers with **multiple strong model answers** that can be shared with students after students attempt the question.

---

# Constraints:

1. Every question must include **three example responses**.
2. All responses must be **fully correct and pedagogically sound**.
3. Responses must **not differ in reasoning quality, conceptual depth, or correctness**.
4. Responses may differ only in:
   - Length  
   - Degree of elaboration  
   - Amount of descriptive detail  
5. The first response must be **concise but complete and correct**.
6. The second response must express **the same ideas**, but with more wording and clarification.
7. The third response must express **the same ideas**, but in a more expanded and well-articulated form.
8. Do NOT introduce new concepts, arguments, examples, or reasoning layers across responses.
9. Do NOT frame responses as basic vs advanced.
10. Responses must read like **clear, natural, high-quality student answers**.
11. IMPORTANT: Create **four versions of every question**:
    - One factual  
    - One focusing on higher-order thinking  
    - One phrased as a *how* question  
    - One phrased as a *why* question  

All four questions must address the **same core topic**, but probe different cognitive dimensions.

---

# Output Format (do not print the question type):

___  

## 1.1 Write the problem here  

**Example Response 1:**  
Response text  

**Example Response 2:**  
Response text  

**Example Response 3:**  
Response text  

___

Prompt - Lägg flervalsfrågor och kortsvarsfrågor i ett interaktivt, fristående HTML-dokument Prompt - Put MCQs and short-answer questions into an interactive self-standing HTML document

Create a single, self-contained HTML file (inline CSS and JavaScript, no external libraries, fonts or images) that works as an interactive practice test. I will paste questions below. Use the content exactly as I wrote it. Do not rewrite, shorten, translate, correct or add to my questions, alternatives, feedback or example responses. Write all interface text (buttons, labels, instructions) in the same language as my questions. If my questions are in more than one language, ask me which language to use for the interface before building.

INPUT
I will paste a mix of two question types:
1. Multiple choice questions, with feedback written for each response alternative. I will mark which alternative is correct (for example with "(Correct)" and "(Incorrect)" after the letter, or the feedback will make it clear). If it is unclear which is correct, or if more than one alternative seems to be correct, ask me before building.
2. Short answer questions, each with a correct example response.
Show the questions in the order I paste them, unless I say otherwise below.

CLEANING OF THE INPUT
- My pasted text may contain labels that belong to the input format, not to the content. Do not display them: question numbers from my input (such as "1.1"), alternative letters (A, B, C and so on), the markers "(Correct)" and "(Incorrect)", and the word "Feedback:" before each feedback text. Display only the actual question text, alternative text, feedback text and example response text, exactly as I wrote them.
- Treat everything I paste as plain text. Keep quotation marks, apostrophes, parentheses, accented and special characters intact, and make sure they cannot break the JavaScript or the HTML.
- Do not show which alternative is correct before the learner has clicked it. The page must not pre-highlight or otherwise hint at the correct alternative.

RANDOM ORDER OF ALTERNATIVES
- Randomize the order of the response alternatives in every multiple choice question each time the page loads. Do not show letter labels next to the alternatives, since they would no longer match the order.
- Keep each alternative connected to its own feedback and its own correct or incorrect status when shuffling.

HOW MULTIPLE CHOICE QUESTIONS SHOULD WORK
- The learner can click any alternative, as many times as they like, until they pick the correct one. There is no limit on attempts and no penalty.
- When an alternative is clicked, show the feedback for that alternative immediately, directly underneath that specific alternative (not in a separate area below the whole question).
- Only one feedback message is visible per question at a time. When the learner clicks another alternative, the previous feedback disappears and the new feedback appears underneath the newly clicked alternative.
- Mark the clicked alternative as correct or incorrect with a clear visual cue. A correct alternative is shown in green and an incorrect alternative in red (background and border), and each also gets an icon and a text label (for example "✓ Correct" and "✗ Incorrect", written in the language of the questions), so the cue does not rely on color alone. The feedback box underneath uses the same green or red styling.
- Only the most recently clicked alternative in a question is marked at any time. When another alternative is clicked, the marking (color, icon and label) on the previously clicked alternative is removed, even if that alternative was the correct one.
- Once the correct alternative has been chosen, the question stays in a "completed" state, with a small visible completed indicator. The learner may still click the other alternatives to read their feedback, and the question remains completed.
- Each question works independently of the others.

HOW SHORT ANSWER QUESTIONS SHOULD WORK
- Show a text box (with a visible label) and a "Submit" button. Do not accept an empty or whitespace-only answer: put the focus back in the text box instead.
- After submitting, keep the learner's answer visible (read-only) and reveal my correct example response below it, with a short prompt such as "Compare your response to the example response." Label my example response clearly (for example "Example response", in the language of the questions). Do not show the example response before the learner has submitted.
- Add a button for the learner to mark that they have compared the two (optional) and a button to edit and resubmit their answer. Keep this simple. When the learner chooses to edit, the example response is hidden again and the question stops showing as completed until the answer is submitted again.
- A short answer question counts as completed when an answer has been submitted.
- Do not try to grade short answers automatically.

LAYOUT AND DESIGN
- Clean, simple and readable. Works well on both desktop and mobile, with no horizontal scrolling.
- Number the questions in the order they are shown (1, 2, 3 and so on), regardless of the numbers in my input.
- Do not add a title or heading for the practice test, and do not add a progress indicator or question counter at the top. Start directly with the first question. Give the HTML page a short neutral document title for the browser tab.
- Accessible: keyboard navigable (alternatives and buttons are real buttons that work with Enter and Space), visible focus states, sufficient contrast, and use aria-live for feedback so screen readers announce it. Set the html lang attribute to the language of the questions.
- No data is sent anywhere and nothing is stored (no localStorage, cookies or network requests). Everything runs locally in the browser. Reloading the page starts over with a new random order.

OUTPUT
Return the complete HTML file as one file I can open directly in a browser. Do not give only partial code. If anything in my input is ambiguous (for example, which alternative is correct, or where one question ends and the next begins), ask me before building.

ANY SPECIAL INSTRUCTIONS (for example a different order, or grouping into sections): [write here or delete]

MY QUESTIONS:
[paste questions here]

Prompt - Gör om flervalsfrågor till en fil som kan importeras Prompt - Get MCQs into importable file

I will give you multiple-choice questions in plain text. Convert them into a QTI 1.2 package for import and give me a downloadable .zip file.

Copy the templates below EXACTLY. Only replace the parts written in CAPITALS. Do not add, remove or rename any other tags or attributes. This structure is tested and works in Canvas.

PACKAGE STRUCTURE
The zip must contain exactly these two files, both at the ROOT of the zip (no folders at all):

  imsmanifest.xml
  assessment.xml

Zip the files themselves, not a folder containing them. Use UTF-8 encoding (the questions contain å, ä, ö). Name the zip file after the quiz title, using only lowercase letters a-z, digits and underscores (for example onskvarda_svarigheter_qti.zip).

IMSMANIFEST.XML (use exactly as written, never change anything)
<?xml version="1.0" encoding="UTF-8"?>
<manifest identifier="quiz_manifest"
          xmlns="http://www.imsglobal.org/xsd/imsccv1p1/imscp_v1p1"
          xmlns:imsmd="http://www.imsglobal.org/xsd/imsmd_v1p2"
          xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
          xsi:schemaLocation="
            http://www.imsglobal.org/xsd/imsccv1p1/imscp_v1p1
            http://www.imsglobal.org/xsd/imscp_v1p1.xsd
            http://www.imsglobal.org/xsd/imsmd_v1p2
            http://www.imsglobal.org/xsd/imsmd_v1p2.xsd">

  <metadata>
    <schema>IMS Content</schema>
    <schemaversion>1.1.3</schemaversion>
  </metadata>

  <organizations/>

  <resources>
    <resource identifier="res_assessment"
              type="imsqti_xmlv1p2"
              href="assessment.xml">
      <file href="assessment.xml"/>
    </resource>
  </resources>
</manifest>

ASSESSMENT.XML (example with one question that has three options, where B is correct)
<?xml version="1.0" encoding="UTF-8"?>
<questestinterop xmlns="http://www.imsglobal.org/xsd/ims_qtiasiv1p2">
  <assessment ident="QUIZ_ID" title="QUIZ TITLE">
    <section ident="S1" title="MCQ">
      <item ident="I_1" title="Fråga 1">
        <itemmetadata><qtimetadata>
          <qtimetadatafield><fieldlabel>question_type</fieldlabel><fieldentry>multiple_choice_question</fieldentry></qtimetadatafield>
          <qtimetadatafield><fieldlabel>points_possible</fieldlabel><fieldentry>1</fieldentry></qtimetadatafield>
        </qtimetadata></itemmetadata>
        <presentation>
          <material>
            <mattext texttype="text/plain">QUESTION TEXT</mattext>
          </material>
          <response_lid ident="response1" rcardinality="Single">
            <render_choice>
              <response_label ident="A">
                <material>
                  <mattext texttype="text/plain">OPTION A TEXT</mattext>
                </material>
              </response_label>
              <response_label ident="B">
                <material>
                  <mattext texttype="text/plain">OPTION B TEXT</mattext>
                </material>
              </response_label>
              <response_label ident="C">
                <material>
                  <mattext texttype="text/plain">OPTION C TEXT</mattext>
                </material>
              </response_label>
            </render_choice>
          </response_lid>
        </presentation>
        <resprocessing>
          <outcomes>
            <decvar varname="SCORE" vartype="Decimal" minvalue="0" maxvalue="100"/>
          </outcomes>
          <respcondition continue="Yes">
            <conditionvar><varequal respident="response1">A</varequal></conditionvar>
            <displayfeedback feedbacktype="Response" linkrefid="A_fb"/>
          </respcondition>
          <respcondition continue="Yes">
            <conditionvar><varequal respident="response1">B</varequal></conditionvar>
            <displayfeedback feedbacktype="Response" linkrefid="B_fb"/>
          </respcondition>
          <respcondition continue="Yes">
            <conditionvar><varequal respident="response1">C</varequal></conditionvar>
            <displayfeedback feedbacktype="Response" linkrefid="C_fb"/>
          </respcondition>
          <respcondition continue="No">
            <conditionvar>
              <varequal respident="response1">B</varequal>
            </conditionvar>
            <setvar varname="SCORE" action="Set">100</setvar>
          </respcondition>
        </resprocessing>
        <itemfeedback ident="A_fb">
          <flow_mat><material>
            <mattext texttype="text/plain">FEEDBACK FOR OPTION A</mattext>
          </material></flow_mat>
        </itemfeedback>
        <itemfeedback ident="B_fb">
          <flow_mat><material>
            <mattext texttype="text/plain">FEEDBACK FOR OPTION B</mattext>
          </material></flow_mat>
        </itemfeedback>
        <itemfeedback ident="C_fb">
          <flow_mat><material>
            <mattext texttype="text/plain">FEEDBACK FOR OPTION C</mattext>
          </material></flow_mat>
        </itemfeedback>
      </item>
    </section>
  </assessment>
</questestinterop>

IDENTIFIERS (follow exactly)
- QUIZ_ID: the quiz title in capital letters A-Z and underscores only, no å, ä, ö or spaces (for example ONSKVARDA_SVARIGHETER).
- Items are I_1, I_2, I_3 and so on, with titles "Fråga 1", "Fråga 2" and so on.
- In EVERY question the options are named A, B, C (and D, E if there are more), in the order I give them. The same letters are reused in every question. This is correct, do not number them.
- Feedback identifiers are the option letter followed by _fb: A_fb, B_fb, C_fb. These are also reused in every question.
- The response_lid ident is "response1" in EVERY question.
- Each option has three parts that must match: a <response_label>, a <respcondition continue="Yes"> and an <itemfeedback>. If a question has four options, add all three parts for D. If it has two, remove all three parts for C.
- The single <respcondition continue="No"> block comes last in <resprocessing> and contains the letter of the correct option.

IDENTIFYING THE CORRECT ANSWER
I mark the correct answer in different ways, and the marking may vary between quizzes or even between questions. Examples include an asterisk, bold text, "(correct)" or "(rätt)" after the option, a separate line such as "Answer: B", "Correct answer: B" or "Rätt svar: B", a checkmark, or other similar signals. Work out which option is marked as correct for each question.
- Remove the marking itself from the option text, so students do not see it.
- Keep the options in the order I give them, even if the correct one is not first.
- If you cannot tell with certainty which option is correct for any question, stop and ask me about that question. Never guess.

FEEDBACK
- Every option must have its own <itemfeedback> block with real feedback text.
- Usually I give separate feedback for each option. Put each text in the feedback block for that option.
- If I give only one feedback text for a question, use that same text in all of that question's feedback blocks.
- If you cannot tell which feedback belongs to which option, stop and ask me. Never leave feedback out.
- Use my feedback text exactly as given. Do not add or remove words such as "Rätt." or "Fel."

OTHER RULES
- One <item> per question, all inside the same <section>.
- If a question has more than one correct answer, stop and ask me before continuing.
- Escape special characters in all text: & as &amp;  < as &lt;  > as &gt;
- Keep my wording exactly as given. Do not rephrase, reorder options, or add questions.

FINAL CHECK (do this before giving me the zip, and report the result)
1. The XML is well-formed, and the zip contains exactly imsmanifest.xml and assessment.xml at the root.
2. For every option in every question there is a <response_label>, a <respcondition continue="Yes"> and an <itemfeedback> with matching letters, and every <itemfeedback> contains real feedback text from my input.
3. Every question has exactly one <respcondition continue="No"> block, and its letter is the correct option.
4. No answer marking (asterisks, "(rätt)" and so on) remains in the option texts.
5. The number of <item> blocks equals the number of questions I gave you.
6. List, for each question, which letter you treated as correct and the first few words of each option's feedback, so I can verify.

MY QUESTIONS:
[paste here]
